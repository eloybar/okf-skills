# Overview
The `okf-learn` skill closes the retrospective self-improvement loop in [The Knowledge Loop Lifecycle](/concepts/knowledge-loop.md). While [OKF Maintain Skill](/concepts/okf-maintain-skill.md) performs mechanical post-edit synchronization, `okf-learn` inspects completed or active coding sessions (`transcript.jsonl`) alongside passive zero-token CLI telemetry (`~/.okf/telemetry.jsonl`) and cross-repo skill learning notes (`~/.okf/skill-learnings.jsonl`) to surface and fix documentation and tooling friction.

# Architecture & CLI Modes
- **Script**: Located at [`okf-learn/scripts/learn.js`](/okf-learn/scripts/learn.js).
- **Session & Telemetry Audit (`node okf-learn/scripts/learn.js [<conversation-id> | --latest] [--recent [N]] [--exclude <id>] [--brain-dir <path>] [--json]`)**:
  - **Smart `--latest` & Multi-Runtime Discovery**: Discovers transcripts across both Gemini Antigravity (`~/.gemini/antigravity-cli/brain/<id>/.system_generated/logs/transcript.jsonl`) and Claude Code (`~/.claude/projects/<slug>/<session-id>.jsonl`, `~/.claude-*/projects/`, `$CLAUDE_CONFIG_DIR/projects/`), auto-detects the transcript format (`antigravity` or `claude-code`, deduplicating Claude Code assistant `message.usage` token counts by `message.id`, counting only `user`/`assistant` conversation records toward `stepCount` rather than internal `attachment`/`api-request*` envelope lines, and extracting `inferredWorkspace` from `attachment.snapshot.workingDirectory` when `rec.cwd` is absent), and emits an explicit `conversation.warning` when a requested transcript is missing or has an unrecognized schema. When `--latest` is passed without an explicit conversation ID, `evaluateSkillsPerformance` automatically skips short `<6` step meta-sessions, single-turn `/okf-learn` meta-sessions (`isMetaLearnTranscript`), delegated Antigravity subagent transcripts (`0` `USER_INPUT` steps with `SYSTEM_MESSAGE` records), and user-aborted 0-reply sessions (`summarizeCandidateLines`) in favor of the most recent substantive coding session (`>= 6` steps), and `--recent [N]` summarizes the last `N` (default `5`) substantive sessions across all workspaces (`inferredWorkspace` resolved via `record.cwd`, `attachment.snapshot.workingDirectory`, or `inferWorkspaceFromPath`, gate score, and friction).
  - **Gate Compliance**: Scores adherence to the 4 mandatory OKF Steering Gates (`sessionStartLint`, `preWorkQueries` including `query.js`, `wayfinder_taxonomy.js`, and `okf/` concept/`index.md` reads with JSON-escaped Windows backslash normalization in `isOkfBundleReadPath`, `conceptCitations` across nested `docs/okf/`, root `okf/` paths, and active workspace concept `.md` filenames and hyphenated concept slugs via `collectWorkspaceConceptHints` / `hasConceptCitation`, and `preCompletionMaintain`, which is automatically satisfied in read-only Q&A sessions where zero file edits or mutating commands occurred; mid-turn `resetAt` continuation slices with 0 new user prompts also carry forward pre-reset `preWorkQueries` and `conceptCitations`).
  - **Quantitative Friction**: Detects `queryMisses` (distinguishing `mode: 'file'` vs. `mode: 'search'`, extracting searched terms from `No matching OKF concepts found for search:` or originating `--search` commands while ignoring partial misses inside multi-keyword shell loops that returned concept matches, excluding `read_file`/`Read` outputs, and filtering out mid-session or historical misses that resolve against the workspace's OKF bundle via `isQueryMissResolvedInBundle` using `rankSearchMatches`), `fallbacksUsed` (suffix/basename/directory rescues), `contextBloat` (conversation-scoped `OKF CONTEXT BLOCK` outputs exceeding 40 KB, measured per individual `OKF CONTEXT BLOCK` via `measureOkfContextBlockBytes` so chained shell commands or multiple separate `query.js` invocations in one shell command do not falsely inflate single-query byte counts), `slowCommands` (backgrounded standalone OKF CLI script or `npm run okf:` invocations, excluding compound test-runner commands like `npx jest` and network-bound Git/GitHub PR commands like `git push` or `gh pr`), and `toolErrors` (`edit_file` target-not-found vs. missing files, ignoring user-cancelled Claude Code tool prompts).
  - **Qualitative Learning Signals (`learningSignals`)**: Extracts corrective user turns (`userCorrections`, filtering out `isMeta: true` / `isSidechain: true` / `isCompactSummary: true` records, Claude Code context-continuation summaries, `[Request interrupted by user...]` markers, `tool_result` outputs, injected `SKILL.md` expansions starting with `Base directory for this skill:`, `<command-name>` blocks, attribute-bearing `<pasted_content ...>...</pasted_content ...>` logs, fenced code blocks via `sanitizeUserTurnText`, and non-corrective `"I don't have it"` / `"I don't just..."` / `"don't seem to"` / `"it should be something..."` statements while capturing `"why was it missed"` retrospective prompts via `isUserCorrectionTurn`) and identifies oversized active concepts (`oversizedConcepts` with body > 12 KB) in the bundle, guiding agents to codify lessons as `# Guardrails & Anti-Regression Checklist` items inside source-bound concepts.
  - **Cross-Repo Skill Learnings Queue (`skillLearningsQueue`)**: Reads queued skill-level findings from `~/.okf/skill-learnings.jsonl` (overridable via `OKF_SKILL_LEARNINGS_PATH` or `--learnings`) and synthesizes a `HIGH` priority `skill-backlog` recommendation when entries exist.
  - **Actionable Recommendations**: Synthesizes prioritized (`HIGH` / `MED` / `LOW`) remediation steps, separating `--bind` file-coverage recommendations (`concept-coverage`) from keyword/tag search-coverage recommendations (`search-coverage`).
- **Auto-Binding Remediation (`node okf-learn/scripts/learn.js --bind <file> --concept <concept-rel-path>`)**:
  - Automatically adds a missed or newly discovered workspace file to the target concept's `sources:` frontmatter (preserving CRLF/LF line endings and refreshing `generated.at`) so future [OKF Query Skill](/concepts/okf-query-skill.md) `--file` lookups resolve at Tier 1.
- **Cross-Repo Skill Note Queueing (`node okf-learn/scripts/learn.js --note "<message>" [--skill <name>] [--category <cat>]`)**:
  - Appends a structured skill improvement item (`{ timestamp, workspaceRoot, skill, category, message }`) to `~/.okf/skill-learnings.jsonl` during any external project session so it can be applied inside the `okf-skills` repository.
- **Queue, Telemetry & Session Watermark Reset (`node okf-learn/scripts/learn.js --clear-notes | --reset`)**:
  - `--clear-notes` empties `~/.okf/skill-learnings.jsonl` after skill improvements are applied; `--reset` clears both `~/.okf/telemetry.jsonl` and `~/.okf/skill-learnings.jsonl` and writes a `resetAt` watermark timestamp to `~/.okf/learn-state.json` (overridable via `OKF_LEARN_STATE_PATH` or `--state`) so subsequent `--latest` and `--recent` audits skip pre-reset transcripts and slice continued project sessions to only steps recorded after `resetAt`. Step 4 of `okf-learn/SKILL.md` mandates running `learn.js --reset` unconditionally at the end of every `/okf-learn` execution (across project repos, `okf-skills`, and zero-issue audits alike).
- **Mandatory Fixture Sanitization**: When translating live session findings into regression tests (`scripts/test-lifecycle.js`), concept examples, or `docs/okf/log.md` entries inside `okf-skills`, all real project names, usernames, LAN IPs, drive URIs, and session UUIDs must be anonymized into generic fixtures (`webapp`, `GatewayService`, `Acme`, `jdoe`, `192.0.2.10`, `00000000-0000-4000-8000-000000000001`), enforced by `verifyPublicRepoSanitization` in [Skill Lifecycle & Documentation Synchronization Playbook](/concepts/skill-catalog-sync.md).
