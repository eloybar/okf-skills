Module 1 • Beginner ⏱ 15 Minutes 📄 Read Markdown Lesson

The Crisis of Codebase Amnesia & Why OKF Exists

Why traditional wikis rot, why AI coding agents burn 60–85% of their context window on blind exploration, and how the Open Knowledge Format (OKF) creates a zero-rot memory loop.

1. The Dual Crisis: Wiki Rot & The Agent Cold-Start Tax

Traditional engineering documentation (Confluence, Notion, static ARCHITECTURE.md files) fails because it is decoupled from the Git commit lifecycle. When code changes on Tuesday, the wiki written six months ago silently becomes a lie. Meanwhile, every time an AI coding agent (Google Antigravity, Claude Code, Cursor, Codex) starts a new session, it suffers from complete codebase amnesia — running dozens of blind grep commands and reading 25+ raw files just to build a mental model.

1. Readable

Plain UTF-8 Markdown (.md) viewable in any editor, terminal, or GitHub PR without proprietary viewers.

2. Parseable

Standard YAML frontmatter (---) at the top of every concept so CLI skills extract types, trust tiers, and links in milliseconds.

3. Diffable

Colocated in Git (/docs/okf) so architectural updates travel in the exact same Pull Request as code edits.

4. Portable

Zero vendor lock-in. Works identically across Antigravity, Claude Code, Cursor, Codex, and GitHub Actions CI.

2. Progressive Disclosure via Reserved Files (index.md & log.md)

Instead of dumping an entire documentation folder into an LLM's prompt, an OKF bundle uses two reserved root files:

docs/okf/
├── index.md      # Reserved: Progressive disclosure catalog + "## Not yet specified" frontier
├── log.md        # Reserved: Chronological audit trail under "## YYYY-MM-DD" headings
└── concepts/     # Domain & architectural concept files (each requires a frontmatter "type")

Module 2 • Beginner → Intermediate ⏱ 20 Minutes 📄 Read Markdown Lesson

Anatomy of an OKF Concept & Guided Onboarding (okf + okf-wayfinder)

How to structure concept YAML frontmatter, form an untyped dependency graph with bundle-relative links, scale past 10 concepts, and capture tribal knowledge via Wayfinder interviews.

1. Concept YAML Frontmatter & Bundle-Relative Graph Links

Every non-reserved .md file in an OKF bundle is a Concept and requires a non-empty type key in its YAML frontmatter. Internal links between concepts use bundle-relative absolute paths starting with / (e.g., [MRR Metric](/concepts/revenue-mrr-metric.md)) to form a directed dependency graph.

---
type: Architecture
title: Payment Webhook Processor
description: Handles incoming Stripe webhook events with Redis idempotency locks.
resource: src/payments.js
tags: [payments, stripe, webhooks]
status: stable
---

# Overview
Processes Stripe events idempotently...

# Related Concepts
- [Monthly Recurring Revenue (MRR)](/concepts/revenue-mrr-metric.md)

2. Scaling Past 10 Concepts & Overcoming "Blank Page Syndrome"

When a flat bundle reaches 10 or more concepts, okf-maintain transitions the layout into semantic subdirectories (such as /concepts/) and automatically refactors internal Markdown links. To eliminate "blank page syndrome" on undocumented files, okf-wayfinder runs wayfinder_taxonomy.js to scan your existing vocabulary (existing_types, existing_tags) and identify the undocumented frontier.

Module 3 • Core Focus: OKF v0.2 ⏱ 30 Minutes 📄 Read Markdown Lesson

What Changed in OKF v0.2 & The Problems It Solves

Explore the four architectural breakthroughs introduced in OKF v0.2: Structured Provenance (sources & footnotes), Actor Identity & Trust Tiers (generated & verified), Time-Bounded Freshness (status & stale_after), and Attested Computation contracts.

1. Interactive OKF v0.1 vs. v0.2 Diff & Problem-Solver Explorer

Click each of the four failure modes below to see why OKF v0.1 fell short in multi-agent production environments and how OKF v0.2 solves it:

The Problem Solved: In v0.1, prose # Citations at the bottom of a file couldn't be linked to specific sentences or evaluated for source credibility. OKF v0.2 introduces structured frontmatter sources with credibility signals (author, usage_count, last_modified, usage_window) bound to claims via [^id] Markdown footnotes.

❌ OKF v0.1 (Unstructured Prose Citations)
---
type: Architecture
title: Payment Service
---

Annual plans are normalized by dividing by 12.

# Citations
- Finance Doc: https://docs.acme.internal/asc606
✅ OKF v0.2 (Verifiable Provenance & Footnotes)
---
type: Architecture
title: Payment Service
sources:
  - id: asc606-policy
    title: Enterprise Revenue Policy (ASC 606)
    url: https://docs.acme.internal/asc606
    usage_window: 90d
    credibility:
      author: human:vp-finance
      usage_count: 142
---

Annual plans are normalized by dividing by 12[^asc606-policy].

[^asc606-policy]: Per ASC 606 section 4.2.

The Problem Solved: A bare v0.1 timestamp hid whether a concept was just hallucinated by an agent or vetted by a staff engineer. OKF v0.2 separates generated: { by, at } from verified: [{ by, at }] using actor identifiers (<producer>/<version>, human:<id>, process:<id>) to compute three deterministic Trust Tiers.

❌ OKF v0.1 (Ambiguous Single Timestamp)
---
type: Concept
title: Auth Token Rotation
timestamp: 2026-10-15T09:00:00Z
---
# Who wrote this? Did a human ever check it? Unknown!
✅ OKF v0.2 (Actor Provenance & Trust Tiers)
---
type: Concept
title: Auth Token Rotation
generated:
  by: Antigravity/4.0
  at: 2026-10-15T09:00:00Z
verified:
  - by: okf-lint/1.6.0
    at: 2026-10-15T09:05:00Z
  - by: human:sec-lead
    at: 2026-10-16T14:20:00Z
---
# Computed Trust Tier: human-reviewed

The Problem Solved: Git drift only detects when a code file changes — it cannot detect when an external SLA, vendor contract, or deprecation deadline passes. OKF v0.2 adds explicit status (draft, stable, deprecated) and stale_after (ISO 8601 UTC expiration).

❌ OKF v0.1 (No Lifecycle or Expiration)
---
type: Concept
title: OAuth1 Handshake
timestamp: 2024-06-01T12:00:00Z
---
# Agents keep using this deprecated pattern forever!
✅ OKF v0.2 (Explicit Status & stale_after)
---
type: Concept
title: OAuth1 Handshake
status: deprecated
stale_after: 2025-01-01T00:00:00Z
---
# Flagged automatically by okf-lint & archived by okf-prune!

The Problem Solved: Prose definitions of metrics like "Net MRR" led to different SQL queries across teams. OKF v0.2 introduces type: Attested Computation, binding runtime, typed parameters, inline # Computation code, executor, and attester.

❌ OKF v0.1 (Prose-Only Metric Guessing)
---
type: Metric
title: Monthly Recurring Revenue
---
Sum active subscriptions and divide annual plans by 12.
✅ OKF v0.2 (type: Attested Computation)
---
type: Attested Computation
title: Monthly Recurring Revenue (MRR)
runtime: postgres
parameters:
  - name: as_of_date
    type: date
    default: "2026-10-01"
executor: scripts/run-mrr-report.sh
attester: scripts/verify-mrr-reconciliation.py
---
# Computation
```sql
SELECT ROUND(SUM(...)/100.0, 2) FROM subscriptions ...
```

Closing the Loop — Steering Gates & Context Injection (AGENTS.md + okf-query)

          
How mandatory Pre-Work Grounding Gates and Pre-Completion Verification Gates in AGENTS.md turn passive documentation into active agent guardrails.

        


        
1. The Two Mandatory Steering Gates (okf-steering-version: 1.6.0)

        

          

            
⚡ Gate 1: Pre-Work Grounding Gate

            
Before inspecting or editing code, the agent MUST run okf-query --search or --file <target> and output an explicit Grounding Citation in its response.

          

          

            
⚡ Gate 2: Pre-Completion Gate

            
Before ending its turn after modifying workspace files, the agent MUST run okf-maintain and okf-lint --drift to guarantee 0 errors and 0 warnings.

          

        


        
2. Two-Tier File Resolution in okf-query --file

        
When an agent runs node okf-query/scripts/query.js --file <path>, the script resolves context in two tiers: Tier 1 matches concepts whose resource or sources directly target that file or a parent folder; if none match, Tier 2 (Subsystem Fallback) retrieves concepts documenting sibling files in the same directory so the agent still receives subsystem constraints.

Autonomous Upkeep, Drift Detection & Graph Visualization

          
How okf-maintain eliminates manual upkeep toil, how okf-lint --drift compares Git history against concept timestamps, and how okf-visualize renders interactive Cytoscape.js dependency graphs.

        


        
1. Mechanical Upkeep with okf-maintain

        
Running npm run okf:maintain automatically syncs Git-drifted generated.at timestamps, auto-heals outdated agent steering notices (AGENTS.md, CLAUDE.md), updates the ## Not yet specified frontier in index.md, appends dated entries to log.md, and rebuilds viz.html.


        
2. Static & Git-History Verification with okf-lint --drift

        
When run with --drift, okf-lint executes git log -1 --format=%aI -- <resource> for every concept and warns if the underlying source code was committed more recently than the concept's generated.at timestamp.

Knowledge Hygiene at Scale — Pruning & CI Gates (okf-prune + GitHub Actions)

          
How to audit, archive, or garbage-collect Expired, Deprecated, Ghost, and Orphaned concepts with okf-prune and enforce zero-drift in GitHub Actions CI.

        


        
1. The 4 Decay Categories in okf-prune

        

          

            
1. Expired (--stale)

            
Concepts whose stale_after ISO 8601 timestamp is in the past.

          

          

            
2. Deprecated (--deprecated)

            
Concepts explicitly marked status: deprecated.

          

          

            
3. Ghost Resources (--ghosts)

            
Concepts whose resource points to a local file that was deleted.

          

          

            
4. Orphans (--orphans)

            
Concepts with zero inbound links from index.md or other concepts.

          

        


        
2. Safe Archiving vs. Deletion & The fetch-depth: 0 CI Rule

        
By default, okf-prune moves candidates into archive/, sets status: deprecated and archived_at, and moves their link under ## Archived Concepts in index.md so agents don't ingest obsolete docs while preserving history. In GitHub Actions (.github/workflows/okf-test.yml), always set fetch-depth: 0 on actions/checkout@v4 so okf-lint --drift can read true Git commit timestamps!

🌱 Greenfield Strategy

            
Bootstrap /docs/okf/index.md (okf_version: 0.2), add AGENTS.md gates from Day 1, and let the bundle grow organically with every feature PR.

Never freeze feature work to document 500 legacy files at once. Map the frontier with okf-maintain, interview the top 3–5 critical modules with okf-wayfinder, and document remaining files incrementally as agents touch them.

          

          

            
🛡️ Risk-Based Trust Governance

            
Require human-reviewed + 90-day stale_after on Auth/Billing & Attested Computation metrics; use machine-confirmed for standard internal services.
